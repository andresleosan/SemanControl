# Fase 1 de SemanControl — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** entregar una base local ejecutable de Next.js en Workers, D1 con datos de prueba y autenticación Google con autorización real de los tres roles.

**Architecture:** monolito modular Next.js App Router con OpenNext; D1 es la fuente de roles y vínculos, R2 es privado. El JWT se verifica criptográficamente antes de acceder a datos de negocio. Los cambios de conciliación y apertura aprobados se preparan en el esquema; los endpoints de operaciones pertenecen a Fase 2.

**Tech Stack:** Next.js 16, React, TypeScript, Tailwind CSS 4, Firebase web SDK, jose, OpenNext, Wrangler 4, Vitest y SQLite/Python.

**Spec:** `SPEC_SEMANCONTROL.md`, con los ajustes aprobados por el usuario el 2026-10-14.

## Global Constraints

- Solo Fase 1; no desplegar ni crear recursos remotos ni avanzar a Fase 2.
- Bindings `DB` y `RECEIPTS_BUCKET` en `wrangler.toml`; tipos generados por Wrangler.
- Clientes sin teléfono; referencia obligatoria; dinero en pesos enteros y cantidades enteras.
- Los roles proceden de D1; Google exige correo verificado. Solo ADMIN puede reemplazar un vínculo existente.
- Ningún SELECT ni JSON para WORKER/CLIENT incluye costo; las consultas públicas usan columnas explícitas.
- Stock total incluye bodega y calle; cargar reserva unidades, entregar descuenta total y reserva, devolver libera reserva.
- Transferencia PENDING/OBSERVED descuenta provisionalmente; VERIFIED no vuelve a descontar; REJECTED exige un reverso único y trazable.
- Aperturas y ajustes contables registran responsable y motivo. Saldo a favor permitido y mostrado como tal en fases posteriores.
- Seed sintético: 1 ADMIN, 2 WORKER, 5 productos, 1 recorrido OPEN, 10 clientes #1–#10.

## Review Focus

- JWT firmado por otra clave, expirado o de otro proyecto: 401 sin consulta D1.
- Correo verificado que intenta tomar una tarjeta ligada a otro UID: denegar, sin sobrescribir.
- Usuario que declara rol ADMIN en el cuerpo/header: ignorarlo; D1 controla el rol.
- Dos recorridos que exceden la disponibilidad: restricciones/triggers bloquean sobreasignación.
- Costo en resultados anidados: respuesta fuera de API admin debe rechazarlo y usar DTO explícito.

### Task 3: Identidad y permisos

**Files:** `src/lib/auth/*`, `src/lib/security/*`, `src/middleware.ts`, `src/app/api/auth/session/route.ts`, `tests/auth*.test.ts`, `tests/security*.test.ts`.

**Interfaces:** `Role = ADMIN | WORKER | CLIENT`; `Principal = { userId: string; firebaseUid: string; email: string; name: string; role: Role; clientId: string | null }`; `authenticate(request: Request, env: CloudflareEnv): Promise<Principal>`; `requireRole(principal, roles)`; `verifyFirebaseToken(token, projectId)`; `resolvePrincipal(db, identity)`; `ApiError(status, code, message)`; `errorResponse(error)`.

**Session contract:** POST `/api/auth/session` recibe Authorization Bearer y exige Origin del mismo origen; valida JWT, enlaza solo UIDs vacíos y devuelve `{user: Principal, redirectTo: roleHome}` con cookie HttpOnly SameSite=Lax Secure en HTTPS y duración limitada a exp. GET devuelve misma forma desde Bearer/cookie; DELETE mismo Origin elimina cookie. No crear usuarios STAFF ni conceder roles por token/cuerpo. CLIENT deriva de tarjeta activa; no requiere fila en users. Si hay fila users CLIENT se verifica además su tarjeta. El middleware y los handlers usan roles D1, no headers de identidad inyectados.

**Client interface:** `getFirebaseAuth(): Auth` lazy; `signInWithGoogle(): Promise<UserCredential>`; UI obtiene ID token y llama POST. `roleHome(ADMIN)=/admin/cierre`, WORKER=/ruta, CLIENT=/mi-cuenta; durante esta fase UI abre `/sesion` para comprobar sesión.

**Cost interface:** consultas públicas y admin separadas (`PUBLIC_PRODUCT_COLUMNS`/`ADMIN_PRODUCT_COLUMNS`), `assertAdminApiAccess(principal, pathname)`, DTO explícito y guard recursivo para rechazar `cost_price` fuera de `/api/admin/*`. No endpoints de inventario en esta fase.
